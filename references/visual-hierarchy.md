# 信息层级：先删重复表达，再决定强调

## 先回答四个问题

这是哪个对象？当前是什么结论或待办？判断依据是什么？当前用户下一步能做什么？一个正在回看历史的人还必须知道：这些结论属于当时，不是现在。

焦点可以是主要表格、编辑表单、审核差异或结果列表。不要求加 Hero，不要求加额外的“摘要卡片”。

## 内容处置表

改版前按真实页面写出：

| 内容 | 处置 | 保留信息的去向 |
|---|---|---|
| 重复的申请完成、流程结束、Market 完成 | 合并 | 页头一次准确总结 |
| 已结束的十几个节点 | 后移 | 完整流程/审批记录 |
| 最终交付物 | 前移 | 结果页首屏 |
| 历史模式长蓝色说明 | 替换 | 紧凑的“历史记录·只读”条 |
| 只读目标集群输入框 | 替换 | 可选择复制的文本属性 |
| 当前阻断或失败 | 保留并提升 | 任务区 + 处理动作 |

不要删除互不相同的证据，例如系统执行完成、自动校验通过、申请人确认是三件不同的事。

## 强调预算（设计启发，不是自动合格指标）

正常页面通常 0–1 个主要提交动作；只读页面为 0，结果页可有一个明显的下一步导航入口。优先使用一个聚合通知呈现当前关键问题，多个真正独立的阻断不能为了“只有一个”被隐藏。

首屏不自动堆“申请概况→流程进度→当前状态→结果通知→统计条”。对于审批，先看需要审核的内容；对于交付，先看结果与下一步；对于台账，先看记录。

普通状态不使用大面积饱和背景；不为每个正常步骤绘制完整边框。选中状态与业务完成状态必须分别表达，例如选中的历史节点用描边/下划线，已完成用文字/图标，不能争用同一颜色和底色。

## 检查

去掉颜色仍能读懂任务顺序；隐藏所有装饰后主要内容没有丢失；200% 缩放下仍能找到操作；长技术名称不会挤碎规格和单位。

“更像现代 SaaS”不是验收证据。报告必须指出具体改动和实际观察，例如首屏不再重复三次成功，交付物在折叠线之前出现。没有量测，不写提升百分比。
