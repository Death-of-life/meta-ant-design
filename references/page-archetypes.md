# 页面模板：统一语言，不统一成同一种布局

| 任务 | 模板 | 首屏顺序 | 不默认添加 |
|---|---|---|---|
| 处理很多记录 | queue | 标题/筛选 → 记录 → 批量操作 | KPI、Hero、风险计分 |
| 审核变更 | review | 变更目的 → 影响与差异 → 审核依据 → 操作 | 大流程图、禁用表单 |
| 跟踪交付 | delivery | 执行结论/待办 → 交付物 → 验证 → 日志 | 多条 100% 进度条 |
| 查看完成申请 | result | 最终结果 → 环境/交付物 → 生效配置 → 记录 | 再展示整套进行中页面 |
| 配置多环境资源 | editor | 环境 → 资源分组列表 → 当前资源表单 → 提交边界 | 目录/空列表/空详情三栏 |
| 查看单一对象 | entity | 对象/状态 → 关键属性 → 关联/活动 → 更多信息 | 每组属性一个 Card |
| 修改设置 | settings | 设置范围 → 可编辑组 → 生效规则 → 保存 | 营销 Hero、指标带 |
| 监控总体态势 | overview | 有依据的结论 → 关键证据 → 异常与明细 | 自动伪造健康分数 |

## Review：按角色决定证据顺序

Manager：为什么申请、影响范围、关键成本/资源规模（仅数据存在时）、SRE 结论、审批依据。
SRE：变更差异、规格、目标集群、交付方式、可执行性、需要确认的异常。

共享数据组件，不强行共享整个页面。审批依据绑定后端提供的冻结快照；不能把当前配置伪装成当时的审批材料。不可逆或有重大影响的操作，确认对话框仍要展示对象与影响范围。

## Delivery：至少区分三条事实

执行、验证、验收分别由业务状态决定。`1 项交付完成、4/4 项校验通过、待申请人确认` 可以同时成立。状态标签简洁，但不能把它们合成为“全部完成”。失败时前移失败对象、错误摘要及授权恢复动作；不要只让用户从日志中寻找原因。

## Result：结果先于过程

标题与完成时间 → 环境/交付物结果 → 最终生效配置入口 → 审批与交付记录。已结束流程默认收起；审计事件仍然可完整查阅。不复用当前执行页面的空操作区。

## Editor：两栏优先，而非强制两栏

本次选中的环境是唯一主导航。左栏按资源类型分组，组内列出实例；右栏编辑选中实例。确有大量实例且宽度足够时才证明三栏必要性。无实例只显示一个创建入口。

切环境保留草稿；切资源保留输入/校验上下文；复制环境配置先预览覆盖范围并保留取消路径；尚未填写、配置已填写、已提交、已交付、已验收分别命名。单环境不展示一排空环境标签。

## 布局尺度

阅读页最大宽度参考 1200px，普通表单 920px；数据表与资源编辑器按内容铺开。辅助审核栏约 320px，仅在有独立内容时显示，空间不足时移到正文前后合适位置。顶部流程只描述业务阶段，不暴露内部节点编号、未经过的条件分支数或编排调试信息。
